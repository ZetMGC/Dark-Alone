# Свободный верстак: первый игровой вариант

Ветка `codex/drink-workbench`, задача [WORKBENCH-01](WORKBENCH_01.md), дата 2026-10-27. Владелец выбрал вариант 2 и подтвердил реализацию. Это игровой прототип приготовления на условных TEST-материалах, следующий этап после DRINK-CORE-01.

## Как пользоваться

1. Подойти к задней стойке с бутылками. E — рабочий ракурс, затем E по поверхности или B — приготовление.
2. Слева выбрать чистый шот или высокий стакан. Сосуд можно заменить только пока порция пустая.
3. Удерживать ЛКМ на бутылке и перенести горлышко над стаканом. Колесо увеличивает/уменьшает наклон; удержание ПКМ даёт быстрый налив. Отпускание ЛКМ ставит бутылку вертикально. На жидкости видны струя и поверхность; промах и переполнение оставляют пролив.
4. Для слоёв наклонять понемногу и держать горлышко близко к краю. Начинать с более плотной жидкости. Ложку можно положить у края, чтобы смягчить струю; движения ложкой внутри стакана перемешивают состав.
5. Перенос стакана к шейкеру отправляет порцию внутрь. Взять шейкер, несколько раз поменять направление движения, затем наклонить над стаканом — вернуть напиток. Стакан/загруженный шейкер можно опорожнить над сливом.
6. Перенести наполненный стакан на поднос «Подать гостю». Подача одноразовая, стоит одно деление смены. При активном разговоре ещё одно деление резервируется для его окончания.
7. Escape возвращает к стойке, следующий Escape освобождает ходьбу. Повторное открытие сохраняет порцию и расположение инструментов. Меню, дневник, потеря фокуса и изменение размера окна останавливают удержание/налив. Порция сохраняется только в текущей смене процесса.

Речь гостя продолжается в верхнем правом углу. Чтобы ответить F/цифрой/колесом, закрыть приготовление, отойти от рабочего ракурса и посмотреть на гостя. Колесо внутри верстака управляет бутылкой, ответ не выбирает.

## Реализация и границы

`DrinkWorkbench` рисует собственную поверхность, предметы и струю в логических 1280×720 с сохранением пропорций и полями. Текст использует MSDF; обычные кнопки остаются нативными Control. UI не показывает таблицу плотностей и миллилитров. Модель `DrinkPreparation` хранит фактический состав; струя рассчитывает попадание, темп и высоту, в модель попадает только помещающийся объём. Короткие дозы одного верхнего ингредиента продлевают его слой без разрушения нижних. Отпущенная бутылка не закрывает стакан: при пересечении возвращается на последнее свободное место.

Первый шейкер работает с одной порцией: перенос внутрь/обратно целиком, без одновременного независимого содержимого двух сосудов. При переливе обратно показывается короткая струя. Это ограничение прототипа, не полная симуляция жидкостей. Бутылки пока бесконечны. Материалы `content/drinks/test_materials.json` явно TEST, численные параметры условные, канон и алкогольные рецептуры не заданы. Рецепты, распознавание качества, реакции/разговорчивость/подмешивание и инвентарь ещё не реализованы. Стакан не записывается в checkpoint; схема сохранений не меняется.

Старое меню и API обслуживания сохранены для legacy-профиля. В обычном free-roam Main новый режим включён по умолчанию; `drink_workbench_enabled=false` возвращает прежнее меню. Домашняя дорожка не использует новых API.

## Проверки

`tools/check_workbench.ps1 -Godot <Godot-4.7.2> -Graphics`: импорт, headless, настоящее окно 1280×720 и 960×600. В каждом GPU-прогоне сохраняются три PNG. Проверяются мышь/колесо, слои, промах/переполнение, ложка, шейкер, слив, паузы и возвраты, точный запечатанный состав, одноразовая подача и завершение той же двухделенной смены. Тест использует свои настройки/контент, без записи файлов игрока.

Дополнительно `tools/check_drink_core.ps1`, `tools/check_bar_service.ps1` и весь `tools/check.ps1`. Старый `bar_service_dialogue_test.gd` намеренно выключает новый режим, новый путь проверяет отдельная сцена `tests/parallel/bar/workbench_test.tscn`. Общие check/export-runner по правилам параллельного раунда не меняются; подключение профиля выполняет координатор при интеграции.

Следующий конкретный шаг: рецепты и допуски поверх запечатанного состава/истории операций; затем осмысленная обратная связь гостя. Сначала согласовать TEST-рецепты и представление подсказок на верстаке, сохранив свободное приготовление.

# Диалоги и термины: формат v1

Статус: формат, загрузка и проверка реализованы в DA-020; исполнение, получение терминов и UI — в DA-021. Решение формата: [ADR-0003](decisions/0003-dialogue-content.md). Работа в игре описана в [DIALOGUE_RUNTIME](DIALOGUE_RUNTIME.md).

## Начало работы для автора

1. Изучить готовые примеры: [словарь](../content/glossary/test_terms.json) и [тестовый разговор](../content/dialogues/test_guest.json).
2. Для нового разговора скопировать структуру в новый `.json` непосредственно в `content/dialogues/`. В одном файле может быть несколько диалогов. ID диалогов уникальны во всём наборе файлов.
3. Оставить `test_content: true`, пока контент технический; в видимых названиях использовать `[TEST]`. Это не канонические истории.
4. У каждого узла указать явное завершение или варианты ответа. Не переименовывать существующие ID при редактуре текста.
5. Добавить неизвестные слова в единый словарь `content/glossary/test_terms.json`, затем сослаться на них по ID.
6. Выполнить проверку ниже. Ошибка указывает файл и логический путь поля, например `…test_guest.json.dialogues[0].nodes[1].choices[0].target`. Синтаксические ошибки JSON также содержат номер строки.

После принятия сценария можно сменить маркер документа на `false`; это не заменяет ревью и не подтверждает сюжет автоматически. Не смешивать в одном документе утверждённый и технический контент: маркер относится ко всему документу.

## Проверка

Из корня проекта после первоначального импорта Godot:

```powershell
godot --headless --path . --script tools/validate_content.gd
```

Использовать свою команду или путь к Godot, как в SETUP. Проверяются единый словарь и все `.json` непосредственно в `content/dialogues/`, в отсортированном порядке. Подпапки автоматически не обходятся. Пустой набор пакетов — ошибка. Успех: код 0 и `PASS: content v1, …`. При ошибке код 1, список диагностик в выводе.

Полный набор регрессионных проверок — `tools/check.ps1`. Код загрузчика сам по себе не запускает реплики.

## Общие правила

- Файлы UTF-8; корень — объект с `schema_version: 1`, `test_content: bool` и соответствующим массивом `terms` или `dialogues`.
- Неизвестные поля отклоняются: опечатка `choises` не должна молча скрыть варианты.
- Все ID соответствуют `^[a-z][a-z0-9_]*$`, например `test_guest_intro`; без пробелов, дефисов и заглавных букв.
- Списки объектов представлены массивами с полем ID. Не заменять их объектами вида `{ "id": {…} }`: повтор такого ключа может потеряться при JSON-разборе.
- Названия, текст реплик, описания и говорящий — непустые строки. Допустимы русские буквы и переносы через `\n`.
- Синтаксис читает встроенный `JSON.parse` Godot. Он допускает некоторые отклонения от строгого JSON; писать обычный JSON без комментариев и завершающих запятых. Валидатор проверяет структуру v1, не является универсальным JSON Schema-валидатором.

## Словарь

`terms` — массив, в том числе пустой для диалога без терминов. Каждый элемент содержит только:

| Поле | Тип и смысл |
| --- | --- |
| `id` | Уникальный ID термина во всём словаре |
| `title` | Отображаемое название |
| `description` | Описание для будущего дневника |

Один ID не может иметь две записи. В каталоге к копии записи добавляется `test_content` из документа; исходный JSON не меняется.

## Пакет диалогов

`dialogues` — непустой массив. Поля каждого разговора:

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `id` | Да | Уникально среди всех загруженных пакетов |
| `title` | Да | Название разговора для автора/будущего интерфейса |
| `start_node` | Да | ID существующего начального узла |
| `nodes` | Да | Массив узлов |
| `allow_cycles` | Нет, по умолчанию false | Намеренно разрешить цикл графа |
| `cycle_note` | При allow_cycles=true | Непустое объяснение, зачем нужен цикл и где выход |

Циклы проверяются структурно; даже разрешённый цикл обязан иметь путь к финалу. Неисполнимость условий выбора проверяется будущим исполнителем, а не этим обходом графа.

## Узел и выбор

Каждый узел: `id`, `speaker`, `text`, `end: bool`, `choices: Array`; необязательное `effects: Array` по умолчанию пустое. ID узла уникален внутри разговора. `end: true` требует пустых choices; `end: false` — хотя бы одного выбора. Нет неявных переходов и автоматического завершения по отсутствующему полю.

Каждый выбор: `id`, `text`, `target`; необязательное `required_terms: Array[String]`, по умолчанию пустое. ID выбора уникален **внутри узла**, цель ссылается на узел того же разговора. Порядок массива — порядок ответов. Не использовать индекс кнопки как постоянный ID.

`required_terms` — список известных словарю ID без повторов. Для доступности в DA-021 нужны все перечисленные термины; условие проверяется при выборе. Пустой список означает отсутствие условия по терминам. В v1 нет произвольных выражений, кода, сравнений доверия и флагов.

Все узлы обязаны быть достижимы от start_node и иметь путь к хотя бы одному end-узлу, если игнорировать условия выбора. Валидатор не доказывает, что нужный термин может быть получен на конкретной ветке: для этого в DA-021 нужны проверки состояния и прохождения.

## Эффекты

Поддерживается только объект с полями `effect_id`, `type: "grant_term"`, `term_id`. ID эффекта уникален **во всём разговоре**, term_id существует в словаре. Стабильный ключ для будущей защиты от повтора — пара `(dialogue_id, effect_id)` в контексте прохождения.

DialogueRunner применяет эффекты входа до оценки ответов. Ключ `(dialogue_id, effect_id)` не повторяется за жизнь Runner, в том числе при цикле и повторном начале разговора. Journal отдельно предотвращает дубли термина. configure моделей фиксирует снимок, новая сессия требует новых экземпляров. Политика finish/cancel — ADR-0004 и DIALOGUE_RUNTIME; DA-020 сам по себе эффектов не применяет.

Времени, стоимости обслуживания и других эффектов в v1 нет. Не добавлять `time_cost` или новые type молча: требуется новое решение и согласованное изменение схемы/потребителей.

## API для следующего агента

Реализации — [DialogueCatalog](../scripts/dialogue/dialogue_catalog.gd), [DialogueContentValidator](../scripts/dialogue/dialogue_content_validator.gd).

```gdscript
var catalog := DialogueCatalog.new()
var paths := PackedStringArray(["res://content/dialogues/test_guest.json"])
if not catalog.load_files("res://content/glossary/test_terms.json", paths):
    # Показать диагностику редактору/разработчику, не запускать новое содержимое.
    print(catalog.validation_errors)
    return
var dialogue := catalog.get_dialogue(&"test_guest_intro")
var node := catalog.get_node(&"test_guest_intro", StringName(dialogue.start_node))
```

Каталог принимает весь комплект атомарно. Неудача оставляет прежний принятый снимок; новый пустой каталог остаётся пустым. `is_loaded()` сообщает о наличии принятого снимка, а не об успехе последнего вызова. Поэтому **всегда проверять bool загрузки**, не заменять его `is_loaded()`.

Геттеры возвращают глубокие копии; изменение копии не меняет каталог. Неизвестный ID даёт пустой Dictionary. ID-списки отсортированы, порядок вариантов ответа сохраняется. Каталог не владеет текущим узлом, набором изученных терминов, временем смены или состоянием UI.

## Экспорт и ограничения

В будущих экспортных профилях включить исходные `.json` в фильтры экспорта, поскольку загрузчик читает их через FileAccess. Добавить проверку реальной сборки: проверки в редакторе не подтверждают наличие файлов в дистрибутиве. Сейчас экспорт не настроен.

Произвольный GDScript, пути к скриптам и сериализованные объекты из контента не исполняются. Расширение условий/эффектов требует изменения валидатора, тестов и документации вместе.

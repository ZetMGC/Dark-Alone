# Разговор и дневник: DA-021

Статус: реализовано в DA-021. DA-022 заменяет сферу разговора TEST-гостем и добавляет независимое обслуживание, см. [GUEST_SERVICE](GUEST_SERVICE.md). JSON v1 сохранён. Решение исполнения: [ADR-0004](decisions/0004-dialogue-runtime.md).

## Проверить в игре

1. F5 запускает бар. Нажать J: дневник пока пуст. J или Escape возвращает в бар.
2. Нажать 2, дождаться перехода к стойке. E по золотой метке `[TEST] Разговор`, T или кнопка справа начинают один и тот же разговор.
3. Начальный узел даёт первый термин. «Спросить подробнее» ведёт к объяснению и даёт второй; «Закончить разговор» ведёт сразу к последней реплике.
4. J или кнопка «Дневник» открывает полученные записи. Кнопка возврата, J или Escape возвращают к той же реплике.
5. В последней реплике нажать «Закончить разговор»: расходуется 1 деление времени. Если остаток положительный, навигация восстановится; иначе откроются итоги смены. Повторный разговор при наличии времени доступен, записи не дублируются.
6. «Прервать разговор» закрывает окно без события завершения и расхода времени. Уже полученные записи остаются. Правила 2-делённой смены — SHIFT_FLOW.

Ответы выбираются мышью или через Tab/Enter. При входе в узел фокус на прокручиваемой области, чтобы не пропускать начало длинной реплики; Tab переводит его к ответам. Длинный текст и многострочные ответы прокручиваются, описание недоступного ответа перечисляет недостающие записи.

## Модели

[Journal](../scripts/journal/journal.gd) хранит определения и известные ID в порядке получения. Настраивается один раз, неизвестный и повторный ID возвращают false без события. get_entries и определения возвращают копии. Записи живут до закрытия текущего экземпляра игры; сохранений на диск нет.

[DialogueRunner](../scripts/dialogue/dialogue_runner.gd) хранит копии определений разговоров, текущий ID узла и журнал эффектов. configure принимает принятый каталог и настроенный Journal. Повторная configure отклоняется: новая сессия требует новых моделей. Изменение каталога после configure не подменяет активный разговор.

start открывает start_node и применяет эффекты. choose проверяет ID ответа и все required_terms заново, затем переходит по target. get_choices добавляет в копию каждого выбора available и missing_terms, не меняя исходный JSON. Чтение состояния и обновление UI не выдают термины.

grant_term применяется один раз по паре `(dialogue_id, effect_id)` за жизнь Runner; Journal дополнительно предотвращает дубли терминов. Команды блокируются, пока Runner применяет изменения и отправляет сигналы, поэтому обработчик term_added/node_changed не может вложенно отменить или продвинуть текущую операцию.

Конечный узел остаётся активным с текстом. finish допустим только здесь; он очищает текущее состояние и выдаёт dialogue_finished с ID. cancel выдаёт только dialogue_cancelled. Повторный finish/cancel возвращает false. После finish или cancel можно начать разговор заново, сохранив дневник и журнал эффектов.

## Координация и ввод

[NarrativeSession](../scripts/session/narrative_session.gd) — узел, который владеет моделями и связывает их с DialoguePanel / JournalPanel. Main связывает его mode_changed с камерой, InteractionController, маркерами и HUD. UI не меняет модели напрямую: выбор передаёт тройку ID разговора, узла и ответа через choose_for_node. Устаревшее событие кнопки отклоняется; команды скрытого за дневником или меню разговора тоже не исполняются.

| Режим | Что разрешено | Escape / J |
| --- | --- | --- |
| exploration | Обзор, якоря, взаимодействие; разговор только у стойки | Escape → menu, J → journal |
| dialogue | Ответ, завершение, прерывание, дневник | Escape → menu, J → journal |
| journal | Чтение записей | Escape или J → предыдущий exploration/dialogue |
| service (DA-022) | Выбор напитка, отмена, меню паузы | Escape → exploration без подачи; J не открывает дневник |
| menu | Продолжить или выйти | Escape → предыдущий режим |

Переход камеры — дополнительная блокировка: во время fade нельзя открыть дневник или начать разговор. Меню можно открыть; fade завершается штатно, после него ввод остаётся заблокированным до возобновления. Меню не останавливает всё дерево сцены и не моделирует время смены.

## Где менять код

| Файлы | Назначение |
| --- | --- |
| `scripts/dialogue/dialogue_runner.gd` | Переходы и одноразовые эффекты |
| `scripts/journal/journal.gd` | Модель известных терминов |
| `scripts/session/narrative_session.gd` | Режимы и команды панелей |
| `scenes/ui/dialogue_panel.tscn`, `scripts/ui/dialogue_panel.gd` | Реплика, ответы и действия |
| `scenes/ui/journal_panel.tscn`, `scripts/ui/journal_panel.gd` | Список терминов и возврат |
| `scenes/interaction/dialogue_trigger.tscn`, `scripts/interaction/dialogue_trigger.gd` | Техническая цель с сигналом dialogue_requested |
| `scenes/characters/test_guest.tscn`, `scripts/characters/service_guest.gd` | Используемый в Main наследник технической цели, внешний вид и стакан |
| `scripts/main/main.gd`, `scenes/main/main.tscn` | Композиция, пути JSON, доступность целей и блокировки мира |

Цель требует якорь counter; в DA-022 это уже ServiceGuest, наследник DialogueTrigger, с тем же сигналом и именем узла в Main. Внешность остаётся технической. Расположение и dialogue_id задаются сценой. Пакеты Main перечисляет через экспортированное dialogue_paths; новый JSON сам по себе не меняет набор игры. CLI валидирует все файлы в content/dialogues, поэтому при добавлении пакета нужно также включить его в Main.

## Проверки и продолжение

`tests/dialogue_runtime_test.gd` проверяет модели и настоящий экземпляр main.tscn: обе ветки, условия, циклы, повторное начало, отмену, копии, reentrancy, E через физический луч, Tab/Enter, устаревшие кнопки, блокировку мира, вложенный возврат из journal/menu.

`tools/capture_narrative_preview.gd` создаёт снимки пустого и заполненного дневника, разговора, конечной реплики, меню и длинных текстов. Он использует реальный renderer. Команды — в TESTING. Снимки пишутся в игнорируемую папку artifacts; они не игровой контент.

DA-022 реализует выбранный владельцем короткий список напитков через отдельную модель, без новых эффектов v1. Время/итоги DA-023 и переходы DA-031 уже реализованы; дневник-книга и его модель запланированы в JOURNAL_PLAN до сохранений (Q-06) и финальных историй. Новый эффект в JSON требует отдельного согласованного изменения.

## Как начать

Каждый использует свой clone или отдельный Git worktree. Два агента не работают в одной физической папке: разные ветки в одном каталоге не изолируют файлы. Не менять ветку в чужой рабочей копии.

1. Прочитать AGENTS, README, STATUS, CONCEPT, HANDOFF, свою карточку, ARCHITECTURE/CONTRACTS и указанные в карточке решения. Взять именно назначенную задачу, не первый todo.
2. В чистой собственной копии выполнить `git fetch origin`, `git switch main`, `git pull --ff-only origin main`; создать назначенную ветку через `git switch -c <ветка>`. Если она уже существует, проверить владельца/историю и продолжить её без сброса.
3. Записать `in_progress`, базовый SHA, ветку и имя исполнителя в СВОЕЙ карточке. Сообщить человеку, что задача взята. Резервирование назначено этим документом, не самовольным выбором общего todo.
4. Разрабатывать и проверять на текущей main без ожидания второй задачи. Записывать результаты в свою папку docs/parallel. Общие зависимости в этом раунде читаются как стабильные API.

## Что не пересекается

Точные списки разрешённых файлов находятся в карточках. Всё остальное только читать. У владельца бар/Main/сессионная координация/камера; у коллеги домашняя сцена и домашний контроллер. Общий InteractionController уже умеет register_surface; коллега использует его без изменений. Публичные HomeExploration/FreeRoamCamera/NarrativeSession HOME-контракты и формат сохранений сохраняются; внутренние изменения бара не требуют правок дома.

Обе ветки вправе читать весь проект и запускать общий tools/check.ps1. Созданные движком .uid включать только рядом со своими новыми ресурсами; .godot/builds/artifacts не коммитить. Массовое пересохранение чужих сцен запрещено. Если понадобилось изменить файл второй дорожки или общий API, сначала предложить отдельную задачу координатору, не добавлять её скрыто в свою ветку; оставшуюся независимую часть продолжить.

## Документация без конфликтов

В этом раунде общие README, STATUS, HANDOFF, BACKLOG, ARCHITECTURE, CONTRACTS, TESTING, ROADMAP, AGENTS, CONTRIBUTING, индексы ADR/worklog и tools/check.ps1/check_windows_export.ps1 редактирует только координатор при интеграции. Исключение к обычному правилу AGENTS зафиксировано в самом AGENTS.

Каждый агент обновляет свою карточку (она является источником живого статуса), свой docs/parallel/<направление>/STATUS.md и HANDOFF.md, а при новом решении — собственные CONTRACTS.md/DECISIONS.md. WORKLOG.md ведётся по docs/templates/HANDOFF.md с реальными командами/результатами. У владельца дополнительно тематические документы бара из карточки, у коллеги HOME.md. Так обе ветки обходятся без конфликтующих вставок в начало общих файлов. Общий BACKLOG содержит ссылки и назначение; координатор перенесёт итоговые статусы/контракты/ADR/тесты в общие реестры после ревью.

## Передать результат

Проверить `git diff --check`, область файлов относительно записанного базового SHA, свои критерии и общий регрессионный набор. В своей карточке/WORKLOG указать точные команды, итоговые SHA, ограничения и следующий шаг. Отправить только свою ветку и передать её человеку для ревью; не сливать/не удалять ветку другого и не публиковать релиз как часть задачи.

Координатор может принять любую из двух веток первой: вторая остаётся проверяемой на исходной общей базе. После каждой интеграции — общий набор и отдельный профильный тест принятой дорожки; после обеих — игровой цикл бар → дом → следующая смена, проверка сохранений и Windows-билд. Это общая проверка совместимости, а не зависимость разработки одного исполнителя от другого.

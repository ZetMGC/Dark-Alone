# Настройки между запусками — DA-057

Владелец отложил сюжет и выбрал продолжение технических механик. DA-057 устраняет потерю настроек при закрытии игры. Решение — [ADR-0023](decisions/0023-persistent-preferences.md).

## Игроку

Изменения в Escape-меню сохраняются автоматически после отпускания ползунка/короткой паузы. Сохраняются:

- Ретро-эффект, детализация изображения и громкость фонового звука.
- Скорость обзора и длительность перехода у рабочего места.
- Анимации книги и громкость шелеста страниц.
- Окно/fullscreen (в том числе F11), выбранный монитор, размер обычного окна и развёрнутое состояние.

Статус записи виден в меню. «Сбросить настройки» возвращает исходные параметры, не удаляя знания/смену/домашние наблюдения. «Начать заново» и тестовый сброс прогресса, наоборот, не удаляют предпочтения.

Позиция окна не хранится на диске: при новом запуске оно помещается в доступную область выбранного экрана. Если монитор с сохранённым индексом недоступен, используется доступный текущий экран. Слишком большое окно ограничивается рабочей областью. Внутри одного запуска F11 и смена сцены сохраняют прежнее поведение позиции/размера; новая смена не центрирует окно заново. Экран определяется индексом, без постоянного идентификатора физического устройства.

TEST-лицо, текущий ракурс/рабочее место, скорость набора и размер речи в этот файл не входят. Настройки не являются игровым прогрессом и не меняют checkpoint v1.

## Файл и ошибки

`user://settings/preferences.json`, обычно `%APPDATA%/Godot/app_userdata/Dark Alone/settings/preferences.json` на Windows. Максимум 16 КиБ. Запись во временный `.tmp` с последующим переименованием; временный файл при загрузке игнорируется. Несовместимый/повреждённый файл полностью отвергается до применения, остаются текущие параметры и сообщение в меню. Сам запуск его не удаляет; следующее изменение настроек или явный сброс могут заменить файл.

При ошибке записи старый файл сохраняется, статус сообщает об ошибке; повтор — через 5 секунд или при следующем изменении/выходе. Это не гарантия при отключении питания/сбое файловой системы; одновременная запись нескольких экземпляров не блокируется. Облака/профилей/миграций/резервной истории настроек нет. В headless/встроенном окне дисплейные параметры не применяются; остальные допустимы.

## JSON v1 и модули

Корень содержит ровно version/presentation/camera/book/display. version=1. presentation: retro (bool), ambience (0…1), detail (adaptive/native/classic). camera: sensitivity (0,5…2), transition (0,2…1). book: motion (full/reduced/off), page_volume (0…1). display: fullscreen/maximized (bool), monitor (целое 0…255), size ([ширина 960…7680, высота 600…4320], целые). Размер затем дополнительно ограничивается реальным экраном. Неизвестные поля/версия, дробные целые, бесконечности, неверные типы отвергаются.

PreferenceStore валидирует/пишет файл. PreferenceController связывает существующие модули через preferences_changed, собирает независимый снимок, записывает через 0,35 с тишины и flush при выходе/смене. Display дополнительно отслеживает нативные изменения раз в секунду. Загрузка выполняется при первом Main, после обычной перезагрузки сохраняются текущие параметры в памяти; настройки окна повторно не применяются. Это предотвращает скачок/центрирование между сменами.

Старые модели/сеттеры продолжают работать. Main.preferences_enabled=false полностью отключает чтение/запись настроек для тестов/снимков; Main.preference_store подставляется до входа в дерево. RUN_HANDOFF переносит эту конфигурацию. Новый PreferenceController создаётся Main и не является autoload. UI и системы прогресса не читают JSON напрямую.

## Проверки

check.ps1 включает preference_test и два независимых процесса write/read; изоляция только в user://preference_tests/. Графический тест проверяет F11/размер/подстановку отсутствующего индекса монитора; фактическое физическое отключение второго монитора не проверено. Windows Validation принимает --preference-check, дополнительно --preference-probe=write/read и --preference-directory=<тестовая папка>; -Graphics проверяет восстановление fullscreen в новом процессе. Обычный EXE этих тестовых режимов не содержит. Полные команды — [TESTING](TESTING.md), фактические результаты — [протокол](worklog/2026-10-27-09-persistent-settings.md).

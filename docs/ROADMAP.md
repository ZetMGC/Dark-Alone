# Начальный план разработки

Дата: 2026-10-26. План идёт по проверяемым результатам. Календарные сроки и загрузка людей пока неизвестны: назначить их после первого замера скорости, не считать этапы обещанием срока.

## M0 — Основа и передача проекта

Результат: локальный Git, открываемый проект Godot, стартовая сцена, понятный вход в документацию и воспроизводимые проверки.

Приёмка: `project.godot` указывает на существующую сцену; версия закреплена; кэш исключён из Git; состояние и задачи записаны; новый участник может выполнить SETUP; результаты проверок указаны в STATUS. Общий сервер и первый ревью проходят отдельной задачей DA-002.

## M1 — Перемещение в черновом баре

Реализовано 2026-10-26: DA-010–DA-013 завершены. Переход через fade, граф из четырёх точек, обзор, луч взаимодействия, подсказки и меню. Результаты — в журнале `2026-10-26-02-navigation.md`. Приёмка не означает готовность диалогов, финального арта или оценки комфорта игроками.

Задачи: DA-010 → DA-011 → DA-012 → DA-013. При наличии нескольких людей локацию можно собирать отдельно после согласования формата якорей.

1. Выбрать переход камеры и управление, описать состояние ввода.
2. Собрать бар из простых форм: вход, стойка, стол, дальний угол.
3. Разместить 3–4 якоря и допустимые связи между ними.
4. Подключить взаимодействие и подсказки; проверить пути камеры.

Приёмка: игра стартует у входа; игрок от первого лица достигает каждого разрешённого якоря и возвращается; камера не пересекает препятствия; повторный ввод не запускает несколько переходов; недоступный переход объясняется; подсказки совпадают с управлением. Ручной маршрут записан в TESTING.

## M2 — Первый законченный игровой цикл

Выполнены DA-020–DA-024: данные, разговор/дневник, гость/подача, 2-делённая смена и локальная техническая приёмка полного цикла на Windows release template. Подготовлены сборка и инструкция тестировщику. Q-01/Q-05 решены владельцем. Первый художественный вариант DA-030 и Q-02 также выполнены; запуск коллегой остаётся DA-002, финальный тест другой целевой машины — DA-041.

Задачи: DA-020 → DA-021 → DA-022 → DA-023 → DA-024. Публичные интерфейсы принимаются перед реализацией, затем UI и контент могут готовиться отдельно.

1. Зафиксировать формат узлов диалога и терминов, реализовать проверку данных.
2. Реализовать разговор и выбор реплики, дневник без дублей.
3. Подключить одного тестового гостя и простое действие обслуживания.
4. Привязать продвижение времени к завершённым событиям, завершать смену ровно один раз.
5. Собрать всё в один проход от входа до результата смены.

Приёмка: полный цикл из CONCEPT проходится без редактора; выбор реально меняет ветку; термин появляется один раз; дневник открывается и закрывается без потери диалога; действие обслуживания имеет наблюдаемое последствие; повторное завершение не списывает время; неверные ID данных дают понятную ошибку. Все ветки тестового диалога проверены. Канонический сюжет для этого не требуется.

## M3 — MVP с двумя историями

Художественная цель уточнена владельцем: мрачная PS1-эстетика с современной подачей в духе Mouthwashing. Согласованные требования и предложения параметров разделены в VISUAL_DIRECTION. DA-030 оформил первый вариант бара/TEST-гостя, добавил отключаемый ретро-эффект и регулируемый фон. Q-02 выбран владельцем: серый бар, цветные люди, без рук игрока. Параметры — ART_GUIDE; субъективная оценка и финальная полировка продолжаются по игровым отзывам.

Порядок после первого оформления: **DA-031 → DA-033 → DA-034 → DA-032 при подтверждении Q-06 → DA-040 → DA-041**. DA-033 уже реализована: записи/контекст, индекс/поиск/закладки и перенос знаний. Следующая DA-034 — книга/листание. Дневник ставим после границы смен, чтобы определить жизнь записей; до сохранений, чтобы не переделывать схему; до финальных историй, чтобы авторы работали под устойчивые записи/страницы. Подробности и критерии — [JOURNAL_PLAN](JOURNAL_PLAN.md).

DA-035 — отдельный проход узнаваемых карикатурно-реалистичных лиц, до финализации персонажей DA-040 и после Q-04. Его можно выполнять параллельно с книжным UI через стабильные ID/временные портреты; дневник не ждёт окончательного меша головы.

1. DA-031: короткие переходы дом/работа и граница новой смены.
2. DA-033: модель записей/словарь, навигация и перенос знаний между обычными сменами.
3. DA-034: убедительный дневник-книга, страницы и анимации, чёткий текст и безопасное прерывание.
4. При подтверждении Q-06 — DA-032, версионированный формат и проверка загрузки на устойчивой модели записей; не сохранять ссылки на узлы.
5. После Q-04 — узнаваемые лица DA-035 и финальные истории DA-040, проверка всех веток/словаря; лица можно готовить параллельно дневнику.
6. Довести оформление по отзывам и пройти полный сценарий на чистом компьютере; записать характеристики машины и проблемы.

Приёмка: обе истории завершаются; термины и время согласованы; дневник-книга читается/листается и хранит знания между обычными сменами; лица узнаваемы на игровом расстоянии; UI не перекрывает важные элементы; есть управление громкостью и выход; переходы не блокируют прохождение; отсутствуют TEST-тексты; итоговая сборка запускается без редактора на согласованной целевой ОС. Если сохранения включены, прогресс восстанавливается, повреждённый файл не уничтожает предыдущие данные.

## M4 — После MVP

DA-036 оставляет досье, источники фактов, связи и противоречия дневника предложением до Q-09/Q-04. Если эти механики включаются в MVP отдельным решением, перенести их перед зависящими от них сюжетами и пересмотреть сохранения. Сейчас заявка владельца на дневник-книгу не означает утверждение всех идей расследования.

Решать по результатам игровых тестов: доверие и подозрение, угощение за свой счёт, донос, подпольные действия и сопоставление противоречий. Каждый пункт — отдельная проверяемая гипотеза с оценкой влияния на данные и сюжет.

## Основные риски

| Риск | Практическая мера |
| --- | --- |
| Разрастание сюжета раньше работающего цикла | Один тестовый гость до окончания M2 |
| Камера едет сквозь объекты или вызывает дискомфорт | Выбор перехода в начале M1; явные маршруты или fade |
| Несовместимые модули от разных агентов | CONTRACTS, маленькие изменения, одна интеграционная сцена |
| Состояние осталось только в чате | Обязательные STATUS, BACKLOG и handoff в каждом изменении |
| Конфликты общих сцен и бинарных ресурсов | Составные сцены, явный владелец файла, учёт источников |
| Оценки времени без опыта команды | Замер фактической работы M1, затем календарное планирование |

## Подготовить комплект

1. Слить выбранные изменения в main через обычное ревью. Проверить, что ветка экрана DA-037 тоже включена, если обещаем fullscreen в этом выпуске.
2. В чистой копии переключиться на main и получить изменения (`git switch main`, `git pull --ff-only`). Не сбрасывать чужую незавершённую работу.
3. Выполнить из корня, с закреплённым Godot/шаблонами:

```powershell
pwsh -NoProfile -File tools/prepare_release.ps1 -Tag v0.1.0-alpha.1 -Godot godot
```

Скрипт требует чистый HEAD, совпадающий с обновлённым origin/main, проверяет исходники, собирает Windows и проверяет release template. Создаёт `builds/releases/<tag>/`: именованный ZIP, SHA256SUMS.txt, build-manifest.json и заполненное release-notes.md. Каталоги прежних выпусков не перезаписываются. Он не создаёт тег, не публикует релиз и не устанавливает зависимости. Перед публикацией выполнить графический PLAYTEST на этой сборке и дополнить раздел проверок фактическими результатами. Факт нажатия Publish не заменяет проверку артефакта.

## Выпустить на GitHub

1. Открыть [Releases Dark Alone](https://github.com/ZetMGC/Dark-Alone/releases) → **Draft a new release**.
2. Указать новый тег, например `v0.1.0-alpha.1`, и точный проверенный commit из manifest (Target). Если main уже ушёл вперёд, не выбирать новую вершину вместо проверенного commit.
3. Название: `Dark Alone v0.1.0-alpha.1 — тестовый билд`. Описание взять из подготовленного release-notes.md, проверив отсутствие плейсхолдеров и недостоверных проверок.
4. Прикрепить **именованный ZIP**, **SHA256SUMS.txt**, **build-manifest.json**. Автоматические Source code.zip/tar.gz — исходники, коллегам для игры нужен наш именованный ZIP.
5. Отметить **This is a pre-release**, сначала сохранить draft. Проверить версию/Target/вложения, затем Publish release. Не отмечать альфа-билд стабильным Latest.
6. Скачать прикреплённый ZIP как коллега, сверить SHA256, распаковать целиком и открыть Dark Alone.exe. Дать команде прямую ссылку на конкретный выпуск, а не локальный путь.

Так создаётся неизменяемая точка проверки: версия → commit → manifest → ZIP. После публикации не подменять ZIP исправленным билдом под старым номером; выпускать alpha.2. Если используются immutable releases, все вложения загрузить в draft до публикации. Процесс основан на [официальной инструкции GitHub](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).

## Коллеге

Открыть ссылку выпуска → Assets → скачать `Dark-Alone-v…-windows-x86_64.zip` → распаковать всю папку → запустить EXE рядом с PCK. Godot не нужен. Инструкция START-HERE.md внутри. Сообщать версию, характеристики экрана/Windows/видеокарты, шаги и лог согласно PLAYTEST. Автосохранение знаний/пометок выполняется на начале следующей смены; новые изменения до этой точки могут потеряться при выходе.

Автоматизация GitHub Actions пока не добавлена. Сначала подтвердить этот ручной цикл, права коллег и запуск на другой машине (DA-002). Токены не записывать в проект и не передавать через чат.

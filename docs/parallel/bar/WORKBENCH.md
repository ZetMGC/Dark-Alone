# Свободный верстак: первый игровой вариант

Текущая ветка `codex/workbench-interactions`, [WORKBENCH-03](WORKBENCH_03.md), 2026-10-27, продолжает [WORKBENCH-02](WORKBENCH_02.md) и [WORKBENCH-01](WORKBENCH_01.md). Владелец выбрал вариант 2 и подтвердил реализацию. Это игровой прототип приготовления на условных TEST-материалах, следующий этап после DRINK-CORE-01.

## Как пользоваться

1. Подойти к задней стойке с бутылками. E — рабочий ракурс, затем E по поверхности или B — приготовление.
2. Слева внизу нажать «Взять шот» или «Взять стакан»; галочка показывает выбранный тип. Он появляется на рабочем коврике. Сосуд заменяется только пока порция пустая. Если внутри напиток, сообщение объясняет отказ: сначала перенести посуду над сливом. Состав никогда не пропадает молча. Отдельные кнопки доступны даже при перекрытии левой зоны предметами.
3. Удерживать ЛКМ на бутылке и перенести горлышко над стаканом. Колесо увеличивает/уменьшает наклон; удержание ПКМ даёт быстрый налив. Резкое движение руки раскачивает бутылку и влияет на струю; для точного налива дать ей успокоиться. Ложка, стакан и шейкер также качаются, затем затухают. Касание другой бутылки вызывает лёгкое покачивание без падения/разрушения/расхода её содержимого; отпускание в занятом месте возвращает бутылку на свободное. Промах падает на локальную плоскость стола, лужица расплывается по поверхности. При соприкосновении пятна соединяются, фактический состав и объём суммируются, цвет смешивается по объёму.
4. Для слоёв положить ложку у края стакана и направить мягкую струю к ней, начиная с более плотной жидкости. Без ложки совместимые жидкости перемешиваются даже при медленном прямом наливе. Движения ложкой внутри стакана перемешивают состав. Ложка обязательна как принятое игровое правило, а не универсальное утверждение о реальных жидкостях: плотность/совместимость по-прежнему важны.
5. Перенос стакана к шейкеру отправляет порцию внутрь. Взять шейкер, несколько раз поменять направление движения, затем наклонить над стаканом — вернуть напиток. Стакан/загруженный шейкер можно опорожнить над сливом.
6. Справа находится большая зона «ВЫДАЧА → ГОСТЮ». Перенести туда наполненный стакан: область подсвечивается, порция встаёт на поднос, появляется активная кнопка «Подать гостю →». Нажать её: режим закрывается, тот же состав показывается в шоте/стакане на настоящей стойке перед посетителем, выводится сообщение. Escape — отойти и обернуться к гостю. Одно только размещение на подносе ничего не списывает; можно снова забрать стакан. При отказе передачи порция остаётся целой. Подача одноразовая, стоит одно деление смены. При активном разговоре ещё одно деление резервируется для его окончания.
7. Escape возвращает к стойке, следующий Escape освобождает ходьбу. Повторное открытие сохраняет порцию, запасы и расположение инструментов. Меню, дневник, потеря фокуса и изменение размера окна останавливают удержание/налив/инерцию. Это состояние текущей смены процесса.

Каждая TEST-бутылка в начале смены содержит 500 мл. Уровень и узкая светлая полоска на стекле показывают остаток; пустая бутылка не льётся. На промах и переполнение тоже расходуется содержимое. Замена стакана/открытие режима ничего не пополняют; новая смена начинает со свежего TEST-запаса. Перемещённый влево стакан берётся обычной ЛКМ: реальные предметы имеют приоритет перед зоной выбора чистой посуды, а стакан виден поверх лежащих инструментов.

Речь гостя продолжается в верхнем правом углу. Чтобы ответить F/цифрой/колесом, закрыть приготовление, отойти от рабочего ракурса и посмотреть на гостя. Колесо внутри верстака управляет бутылкой, ответ не выбирает.

## Реализация и границы

`DrinkWorkbench` рисует собственную поверхность, предметы и струю в логических 1280×720 с сохранением пропорций и полями. Текст использует MSDF; обычные кнопки остаются нативными Control. UI не показывает таблицу плотностей и миллилитров. Модель `DrinkPreparation` хранит фактический состав; струя рассчитывает попадание, темп и высоту, в модель попадает только помещающийся объём. Короткие дозы одного верхнего ингредиента продлевают его слой без разрушения нижних. Отпущенная бутылка не закрывает стакан: при пересечении возвращается на последнее свободное место.

Первый шейкер работает с одной порцией: перенос внутрь/обратно целиком, без одновременного независимого содержимого двух сосудов. При переливе обратно показывается короткая струя. Это ограничение прототипа, не полная симуляция жидкостей. Физика предметов — пружины/импульсы 2.5D; стук визуальный, звукового эффекта пока нет. `DrinkBottleStock` отдельно от UI хранит конечные запасы; `DrinkSpillSurface` — состав луж/их растекание и объединение (цвет усредняется и для несовместимых материалов, отдельные фазы пятен пока не рисуются). Для ограничения детализации более 64 луж объединяется ближайшая пара без потери состава. Склад/покупка/замена бутылок/уборка ещё не реализованы. Материалы `content/drinks/test_materials.json` явно TEST, численные параметры условные, канон и алкогольные рецептуры не заданы. Рецепты, распознавание качества, реакции/разговорчивость/подмешивание ещё не реализованы. Стакан/остатки не записываются в checkpoint; схема сохранений не меняется.

Старое меню и API обслуживания сохранены для legacy-профиля. В обычном free-roam Main новый режим включён по умолчанию; `drink_workbench_enabled=false` возвращает прежнее меню. Домашняя дорожка не использует новых API.

## Проверки

`tools/check_workbench.ps1 -Godot <Godot-4.7.2> -Graphics`: импорт, headless, настоящее окно 1280×720 и 960×600. В каждом GPU-прогоне сохраняются шесть PNG, включая готовую выдачу и результат у гостя. Проверяются мышь/колесо, слои с ложкой и смешивание без неё, промах/переполнение и сохранение объёма при расходе бутылки, исчерпание запасов, инерция/затухание/пауза всех предметов, горизонтальные/вертикальные касания бутылок, состав/цвет/объединение луж, лужи на разной глубине, подбор стакана из обеих левых зон, явные кнопки посуды/защита непустой порции, ложка, шейкер, слив, возвраты, подготовка на подносе без списания, отказ и успешная выдача кнопкой, точный запечатанный состав/3D-сосуд на столешнице, одноразовая подача и завершение той же двухделенной смены. Тест использует свои настройки/контент, без записи файлов игрока.

Дополнительно `tools/check_drink_core.ps1`, `tools/check_bar_service.ps1` и весь `tools/check.ps1`. Старый `bar_service_dialogue_test.gd` намеренно выключает новый режим, новый путь проверяет отдельная сцена `tests/parallel/bar/workbench_test.tscn`. Общие check/export-runner по правилам параллельного раунда не меняются; подключение профиля выполняет координатор при интеграции.

Следующий конкретный шаг: рецепты и допуски поверх запечатанного состава/истории операций; затем осмысленная обратная связь гостя. Сначала согласовать TEST-рецепты и представление подсказок на верстаке, сохранив свободное приготовление.

# ADR-0004: Исполнение разговоров и дневник сессии

Дата: 2026-10-26. Статус: Accepted для DA-021. Основание: продолжение после слияния DA-020 владельцем.

## Решение

Journal и DialogueRunner — независимые RefCounted-модели. Они настраиваются один раз из принятого каталога и хранят собственные копии определений; перезагрузка каталога не меняет уже идущую сессию. Для новой игры нужны новые модели. Journal хранит известные термины в порядке получения и выдаёт событие только при первом добавлении известного ID.

Runner начинает разговор с start_node, применяет grant_term при входе в узел и проверяет все required_terms при выборе. Эффекты помечаются ключом `(dialogue_id, effect_id)` один раз за жизнь Runner, до отправки сигналов. Изменение состояния защищено от повторного вызова команд из обработчиков сигналов. Чтение модели и перерисовка интерфейса не применяют эффекты.

Конечный текст остаётся видимым, пока игрок не нажмёт «Закончить разговор». Только явный finish на конечном узле испускает dialogue_finished, ровно один раз. Прерывание cancel возвращает к исследованию с отдельным dialogue_cancelled, без finish; уже полученные термины остаются. Повторное начало разрешено после finish/cancel, с сохранением дневника и журнала эффектов. Расход времени ещё не реализован и будет принят в DA-023.

## Модальный ввод

NarrativeSession координирует модели и панели, Main связывает его режим с камерой, контроллером взаимодействия и меню. Режимы exploration, dialogue, journal, menu; переход камеры дополнительно блокирует открытие панелей. Journal помнит режим возврата; меню помнит текущий режим, включая journal поверх dialogue. Escape закрывает дневник, в разговоре открывает меню, в меню возобновляет предыдущий режим. Прерывание разговора — отдельная явная кнопка.

Панель передаёт ID разговора, узла и выбора: устаревшее событие от прежнего узла отклоняется. На экране дневника и в меню выборы тоже не исполняются. Камера не получает стрелки и мышь, пока открыт любой модальный экран.

## Проверяемый вход и границы

В DA-021 для проверки интерфейса у стойки есть явно техническая цель `[TEST] Разговор`, доступная только из якоря counter. E по метке, T или кнопка запускают тот же разговор. Это заготовка взаимодействия, не NPC и не механика обслуживания DA-022.

J открывает/закрывает дневник из исследования или разговора; полученные термины доступны без сохранения на диск. UI поддерживает мышь и Tab/Enter; длинные реплики и дневник прокручиваются. Время, сохранения, канонический сюжет и обслуживание не добавляются этим решением.

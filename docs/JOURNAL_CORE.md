## Игроку

J открывает дневник в баре, разговоре, итогах и дома. Слева индекс записей, справа описание/источник; поиск по заголовку и тексту, фильтры «Все», «Новые», «Закладки». Стрелки под записью сначала листают описание, затем перебирают результаты текущего фильтра, «Закладка» сохраняет выбранную запись. • означает непрочитанную запись, ★ — закладку. Открытие выбранной записи отмечает прочитанной только её, не весь дневник.

Фильтр не удаляет выбранную запись: после чтения запись может исчезнуть из «Новых», но её текст остаётся доступным с подписью «Открытая запись вне фильтра». Возврат из дневника ведёт к прежней реплике/экрану, чтение и поиск не тратят время. Поиск получает буквы J/T/B, игровые горячие клавиши при вводе текста не срабатывают; Escape возвращает назад.

Через «Домой» → «На работу · следующая смена» сохраняются знания, источники, прочитанность, закладки и выбранная запись. Номер смены увеличивается, часы/заказ/разговор сбрасываются. «Сбросить тестовый прогресс» очищает дневник и возвращает смену 1. DA-032 сохраняет начало следующей смены после дома; после перезапуска загружается этот checkpoint, см. [SAVES](SAVES.md).

## Данные и API

Словарь JSON v1 не менялся. Определения по-прежнему id/title/description. `Journal.get_entries()` возвращает прежние поля плюс:

| Поле | Правило |
| --- | --- |
| entry_id | `term:<term_id>`, постоянный ключ записи |
| learned_order | Номер первого получения, начинается с 1 |
| source | Пустой Dictionary для прежнего ручного add_term, иначе dialogue_id/node_id/speaker/shift |
| read / bookmarked | Булевы признаки, не часть определения слова |
| reading_offset | DA-034: позиция символа исходного описания, 0…длина, переносится между сменами |

`add_term(term_id, source={})` принимает один термин один раз. У контекста ровно четыре ключа, строковые ID/speaker непусты, shift — положительный int; это проверка структуры, ссылки поставляет принятый DialogueRunner. Первый источник не переписывается при повторе. Getter-методы возвращают глубокие копии; `get_definition` не содержит прогресс.

Новые методы: get_entry(id), get_filtered_entries(query="", section=&"all"), get_unread_count(), select_entry(id), set_bookmarked(id,value), matches_catalog(catalog). Поле selected_term_id доступно для чтения. select_entry отмечает запись прочитанной; закладка идемпотентна. Неизвестные ID/разделы, невалидный source и вложенные изменения отклоняются. Прежние однопараметрический add_term и get_entries совместимы. Сигналы entry_changed/selection_changed дополняют term_added.

Runner.configure получает необязательный shift_number=1 и передаёт контекст узла в Journal при grant_term. Идентификаторы разговора/узла остаются внутри данных, игрок видит speaker и номер смены. Поиск/фильтры — представление, номер страницы никогда не служит ID записи.

## Владение и перенос

NarrativeSession.configure добавляет в конце shared_journal: Journal=null и number: int=1. Непустой настроенный журнал допускается только при полном совпадении определений каталога; скрытого обновления данных нет. configure_shift допускает такой журнал до начала действий. Обычная смена переносит ссылку на Journal через одноразовую мета-запись SceneTree `dark_alone_journal_handoff` с точным scene_file_path и следующим номером. Новая Main проверяет/потребляет запись; после успешного перехода её нет. Ошибка структуры/каталога показывает ошибку настройки, не маскируется пустым журналом. При отказе reload мета-запись убирается.

Это только передача в памяти на время перезагрузки сцены, не autoload, шина событий или save-файл. Прямой тестовый reset не передаёт журнал. Старые объекты UI/Runner освобождаются, новый Session подписывается на тот же Journal. Новые эффекты, кроме grant_term, потребуют отдельного решения о журнале применения между сменами.

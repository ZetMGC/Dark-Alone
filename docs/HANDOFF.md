# Передача проекта

## Продолжить работу за одну сессию

1. Начать с README и STATUS. Проверить ветку, `git status`, последние коммиты и актуальность копии относительно общего сервера, если он уже есть.
2. Прочитать CONCEPT: утверждённое, предложенное и нерешённое отделены. Для технической работы — ARCHITECTURE, CONTRACTS и ADR.
3. Найти последнюю запись `docs/worklog/`. Выбрать свободную задачу BACKLOG, проверить зависимости. Не начинать с первого случайного TODO в коде.
4. Запустить проверки основы. Если они не проходят до изменения, записать исходную проблему.
5. Сделать ограниченную задачу, проверить её критерии, обновить документы и оставить handoff по шаблону.

## Что считается источником истины

Последняя сессия: [DA-003](worklog/2026-10-26-13-branch-consolidation.md), текущая ветка `main`. Все готовые изменения объединены, восемь рабочих веток удалены после проверки сохранности коммитов. Следующий шаг DA-039: подготовить первый GitHub Pre-release из чистого main по RELEASES, затем TEST-лица DA-035. DA-038 ждёт концепт записей владельца; Q-04/Q-06 остаются открытыми. F11/экраны — DISPLAY, книга — JOURNAL_BOOK.

- Код и данные описывают фактическое поведение.
- STATUS описывает текущую готовность и ограничения.
- CONCEPT описывает продуктовые требования и вопросы.
- BACKLOG описывает задачи, владельцев и зависимости.
- CONTRACTS и ADR фиксируют публичные интерфейсы и причины решений.
- Worklog хранит историю проверок и передачу; старые записи не переписываются под новое состояние.

Если документы расходятся с кодом, сначала явно указать расхождение. Не считать чат, память агента, старый handoff или картинку единственным актуальным источником.

## Минимум перед завершением каждой задачи

Обновлены статус задачи и состояние проекта; записаны выполненные проверки и ограничения; есть следующий конкретный шаг; изменённые интерфейсы отражены в CONTRACTS; существенные решения оформлены ADR. Для частичной работы указаны файлы и точка остановки. Изменения переданы через Git, когда сервер настроен.

Если задача будет продолжена другим агентом, достаточно передать ему рабочую копию и такую инструкцию:

> Прочитай AGENTS.md, README.md, docs/STATUS.md и docs/HANDOFF.md. Проверь Git и последнюю запись worklog. Продолжи следующую доступную задачу из BACKLOG с учётом зависимостей. Не считай предложения интерфейсов реализованными. После работы обнови состояние, проверки и передачу.

Эта инструкция не даёт агенту права самостоятельно менять сюжет, публиковать проект или выбирать лицензию.

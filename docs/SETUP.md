# Запуск и рабочая среда

## Новый участник

1. Клонировать `https://github.com/ZetMGC/Dark-Alone.git` в отдельную папку и использовать актуальный main: после DA-051 он включает окружение/настройки камеры, исследуемый TEST-дом и исправление горизонта DA-050. Ветка feat/game-improvements сохранена как источник интеграции. Не делить один рабочий каталог через OneDrive между редакторами: нужны независимые копии. Опубликованный alpha.2 старее исходников main.
2. Установить Git и скачать [Godot 4.7.2 Standard](https://godotengine.org/download/archive/4.7.2-stable/). Закреплённая версия хранится в `.godot-version`. Файл движка не включён в репозиторий.
3. В менеджере проектов Godot выбрать Import → корневой `project.godot`. При первом открытии дождаться импорта.
4. Нажать F5. ПКМ + мышь / стрелки — обзор, 1–4 — переходы. У стойки E по гостю или T — разговор, B — подать напиток. Tab/Enter или мышь — выбор; J — дневник. Escape из дневника/обслуживания возвращает назад, в разговоре открывает меню. Клавиша 2 ведёт за стойку. Завершённый разговор и подача тратят по одному из двух делений; затем доступны итоги и новая смена. Инструкции — DIALOGUE_RUNTIME, GUEST_SERVICE и SHIFT_FLOW.
5. Прочитать STATUS и HANDOFF, выбрать задачу, создать ветку.

Готовая сборка запускается без редактора — см. [PLAYTEST](PLAYTEST.md). Разработчику, который готовит архив, нужен [BUILD](BUILD.md).

## Проверки в PowerShell

Если `godot` есть в PATH:

```powershell
pwsh -NoProfile -File tools/check.ps1
```

Если нет, передать абсолютный путь к Standard console executable:

```powershell
pwsh -NoProfile -File tools/check.ps1 -Godot 'C:\Tools\Godot\Godot_v4.7.2-stable_win64_console.exe'
```

Путь — пример, его нужно заменить своим. Если используется Windows PowerShell 5.1, вместо `pwsh` можно вызвать `powershell`. Не менять глобальную execution policy ради проекта. Если политика организации запрещает скрипты, использовать ручные команды из TESTING согласно её правилам.

Скрипт проверяет версию, импорт, Main, M1, контент, загрузчик, разговор, Journal, обслуживание, смену, перезапуск, модальные экраны и старт. Коды ошибок и сообщения `ERROR:` считаются провалом. Визуальная проверка отдельная: TESTING содержит команды снимков. Авторам контента доступна команда из DIALOGUE_CONTENT.

## Частые проблемы

Дневник DA-034: инструкция и команды снимков — [JOURNAL_BOOK](JOURNAL_BOOK.md). Полный check.ps1 включает книгу; для изолированной проверки: `godot --headless --path . res://tests/book_test.tscn`. Системные шрифты не нужно копировать в проект: предусмотрен fallback, разбиение на страницы пересчитывается на машине запуска.

- Другой Godot: не пересохранять проект новым движком молча; свериться с `.godot-version`.
- Нет `godot` в PATH: указать `-Godot` с полным путём.
- После переноса пропали ресурсы: сохранить `.uid` и `.import` sidecar-файлы, проверить регистр путей и повторить импорт. `.godot/` не переносить.
- Конфликт сцены: не выбирать весь «свой» или «чужой» файл автоматически; согласовать владельца, затем открыть и проверить сцену.
- Невозможно запустить движок: записать причину в handoff; просмотр текста сцены не заменяет запуск.

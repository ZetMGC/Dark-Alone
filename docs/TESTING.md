# Проверки

## Основа и M1 — доступно сейчас

Из корня репозитория выполнить `tools/check.ps1`, указав путь к закреплённой версии, если её нет в PATH. Скрипт включает:

```powershell
godot --version
godot --headless --path . --editor --import
godot --headless --path . --script res://tests/smoke_test.gd
godot --headless --path . --script res://tests/navigation_test.gd
godot --headless --path . --quit-after 5
git diff --check
```

Последняя команда выполняется отдельно: она не входит в скрипт Godot. Без PowerShell три команды движка можно запускать напрямую на другой ОС. `godot` здесь — команда или путь к executable. При коде 0 всё равно проверить вывод на ошибки скриптов и ресурсов.

Smoke-тест загружает именно `application/run/main_scene`, создаёт её экземпляр и проверяет вход в дерево. Это узкая проверка готовности основы. Она не подтверждает игровые механики и качество изображения.

M0-экран заменён играбельной сценой. Ручной маршрут M1: F5 → вход → стойка → стол → угол → вход, затем обратный обход. Проверить ПКМ и стрелки, R, E на метке, цифры 1–4 и кнопки; повторные нажатия во время fade; отказ вход → стол; Escape и возобновление, выход через меню. Изменить размер окна и проверить читаемость. Ошибки записать. Headless-проверка не оценивает комфорт обзора.

`tests/navigation_test.gd` автоматически проверяет восемь направленных связей, сигналы ровно один раз, отсутствие промежуточных поз камеры, сброс и ограничение обзора, блокировку ввода, события InputMap, команду HUD, коллизии конечных поз, ошибочные графы и перекрытие луча стеной. У теста есть общий timeout 20 секунд. Количество внутренних проверок может зависеть от числа кадров; критичны отсутствие FAIL и код 0.

Для воспроизводимого визуального обзора на машине с графикой:

```powershell
godot --path . --script tools/capture_preview.gd --resolution 1280x720
```

Результат: `artifacts/m1_entry.png`, `m1_counter.png`, `m1_table.png`, `m1_corner.png`. Папка исключена из Git. Просмотреть все четыре изображения: интерфейс должен читаться, конечные позы не должны попадать внутрь мебели. Команда использует реальный renderer, режим `--headless` для неё не подходит.

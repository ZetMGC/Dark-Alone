# Совместная работа

## Перед началом

Пройти `docs/SETUP.md`, прочитать `docs/STATUS.md`, согласовать задачу из `docs/BACKLOG.md`. Правила для агентов — в `AGENTS.md`. Для людей действуют те же требования к проверкам и передаче контекста.

Рабочая ветка: `feat/DA-010-anchor-camera`, `fix/DA-xxx-description` или `docs/DA-xxx-description`. В `main` попадают связные проверенные изменения через ревью коллеги после настройки общего сервера. Пока сервер не выбран, ветки и коммиты существуют только локально.

## Как делить работу

| Направление | Основные файлы после их создания | С кем согласовывать |
| --- | --- | --- |
| Локация | `scenes/levels/`, `assets/environment/` | Камера: положение якорей и маршруты |
| Камера и взаимодействие | `scripts/player/`, `scenes/player/` | Локация и координатор смены |
| Диалоги и контент | `scripts/dialogue/`, `content/dialogues/`, `content/glossary/` | Дневник и UI: контракт событий |
| UI и звук | `scenes/ui/`, `scripts/ui/`, `assets/audio/` | Диалоги: ввод и состояние интерфейса |

Это направления ответственности, а не назначенные люди. Исполнители пока не определены. Системы времени и сохранений берёт отдельная задача после основного цикла. Количество коллег не зафиксировано.

Не редактировать одну общую сцену одновременно. Ветку не считать блокировкой файла. Указать владельца в задаче; при наличии общего трекера и бинарных файлов позже решить, нужен ли Git LFS и блокировка. Пока LFS не настроен, не добавлять большие наборы текстур, видео и исходники моделей.

## Перед ревью

1. Сверить изменения с критериями задачи. Удалить временный код и проверить `git diff --check`.
2. Запустить проверки из TESTING. При изменении поведения пройти ручной сценарий.
3. Обновить STATUS, BACKLOG, журнал сессии; при изменении интерфейсов — CONTRACTS и ADR.
4. В описании изменения указать: проблему, итоговое поведение, проверку, ограничения, влияющие на коллег.
5. Не смешивать реализацию механики, переработку сцены и апгрейд движка в один набор изменений.

Коммиты: `chore: initialize Godot foundation`, `feat(DA-010): add anchor camera`. Название должно объяснять результат.

## Готовность задачи

Реализованы критерии; нет новых ошибок запуска; проверки записаны; документация соответствует коду; следующий участник понимает ограничения и продолжение. Нельзя писать «готово», если результат существует только в чате или на незакоммиченном компьютере.

Публичная лицензия не выбрана. Не добавлять сторонние материалы без записи в `docs/ASSETS.md` и проверки прав.

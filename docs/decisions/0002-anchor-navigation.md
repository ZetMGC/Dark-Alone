# ADR-0002: Якоря и ввод первого прототипа

Дата: 2026-10-26. Статус: Accepted для M1. Задачи: DA-010–DA-013. Продуктовое основание: автор разрешил начать разработку по подготовленному плану; первое лицо и фиксированные якоря сохраняются.

## Выбор

Используем короткое затемнение: fade-out → установка позы целевого якоря → fade-in. Положение камеры во время видимой части кадра не интерполируется. Это исключает видимый проезд через мебель и снижает риск дискомфорта. Полная длительность около 0,5 секунды, настраивается у AnchorCamera.

Рассмотрены два варианта: плавная интерполяция требует маршрутов и проверки геометрии каждого ребра; fade требует только безопасных конечных поз. Для первого небольшого бара выбран fade. Плавное движение оставить будущим отдельным решением без изменения публичных команд камеры.

## Данные и контракты

`AnchorPoint` — Area3D, его глобальный transform задаёт позу камеры. Поля: уникальный `anchor_id`, `display_name`, `neighbours`. Это направленный граф: обратный переход нужно указать явно. Четыре якоря M1 образуют кольцо: entry ↔ counter ↔ table ↔ corner ↔ entry. Высота камеры 1,65 м. Масштаб узлов якорей — единичный.

`AnchorCamera.configure(anchors_root, initial_id)` сначала валидирует весь граф (пустые/дублирующиеся ID, неизвестные соседи, самоссылки, повторы, позы), затем устанавливает стартовую позу без игровых сигналов. Ошибки доступны через `validation_errors`. Неуспешная конфигурация не подменяет старый граф.

Команды `can_move_to`, `request_move` и сигналы `transition_started`, `anchor_reached` приняты из CONTRACTS. Принятый переход имеет ровно одно начало и завершение. Повторные запросы, текущий, неизвестный и несоседний якорь отклоняются. Пауза блокирует новые действия, текущий fade заканчивается штатно. Удаление камеры отменяет её tween.

Взаимодействия — общий тип `Interactable3D` с `is_available`, `get_prompt`, `interact`. Луч камеры проверяет слой 1 (препятствия) и слой 2 (цели); стены перекрывают выбор. Кнопки маршрута — альтернативный способ выбрать разрешённый переход без прицеливания. Применение запроса ещё раз проверяет доступность.

## Управление M1

- ПКМ + мышь — обзор, ограниченный по вертикали; отпускание ПКМ освобождает курсор.
- Стрелки — обзор с клавиатуры; R — вернуть направление текущего якоря.
- E — взаимодействовать с доступным якорем под прицелом.
- 1 / 2 / 3 / 4 либо кнопки маршрута — вход / стойка / стол / угол. Недоступный прямой переход не выполняется и объясняется.
- Escape — меню с продолжением и выходом. Потеря фокуса освобождает мышь; движение не возобновляется само.

Свободной ходьбы нет. В M1 используются режимы exploration, transition, menu; остальные режимы появятся вместе с диалогами и дневником. Переназначение клавиш, полноценная пауза будущих игровых систем и оценка комфорта игроками ещё не выполнены.

## Границы

Решение определяет только технический прототип. Оно не утверждает финальный свет, планировку, время, сюжет и обслуживание. Коллега изменяет бар в сцене локации, камеру — отдельно; главная сцена только связывает модули.

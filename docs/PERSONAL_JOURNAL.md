# Личные страницы: контракт и продолжение

DA-065, ADR-0028. Определения слов по-прежнему в content/glossary. Личный текст игрока — в JournalNotebook и затем user://checkpoint на прежней границе следующей смены. Не записывать личные данные в исходники/сцены.

## Модель

Journal.notebook: RefCounted JournalNotebook, сигнал changed после принятой команды. get_notes(sheet), get_recipes(), get_links(), export_data() возвращают глубокие копии. Общий монотонный положительный int ID заметок/рецептов, не индекс массива.

- add_note(text: String, position: Vector2, sheet: int=0) -> int: ID либо -1; 1–320 знаков без пустоты, конечные координаты 0..1, восемь разворотов по восемь заметок (64 всего).
- update_note(id, text), move_note(id, position), toggle_circle(id), remove_note(id) -> bool. Удаление убирает входящие/исходящие связи.
- link_notes(from, to), unlink_notes(from, to) -> bool. До 128 направленных связей в пределах одного разворота; без самоссылок/дублей/несуществующих ID.
- add_recipe(text: String) -> int, update_recipe(id, text), remove_recipe(id) -> bool. До 32 свободных рецептов по 1–4000 знаков. Это личный текст, не исполняемая рецептура.
- restore_data(Dictionary) -> bool: полная валидация до замены, без частичной мутации при ошибке.

Опциональный journal.notebook в checkpoint v1:

```json
{"notes":[{"id":1,"text":"Личная мысль","x":0.2,"y":0.4,"sheet":0,"circled":true}],"links":[],"recipes":[{"id":2,"text":"Название\nСостав и способ"}]}
```

Пустое поле не экспортируется. Journal.restore_progress принимает entries/selected и опциональные annotations/notebook, отвергает неизвестные ключи/плохие ID/координаты/дубли/ссылки атомарно. Старые файлы читаются; CheckpointCodec/Store/версия 1/отпечаток контента прежние. Закрытие книги не создаёт немедленного файла. Новый Journal новой игры пуст, обычная смена переносит прежний Journal вместе с notebook.

## Представление и ввод

JournalPanel.select_section(value: StringName) -> bool: words/notes/recipes, анимированный переход без расхода времени. Последняя вкладка живёт на экземпляре панели, первоначально words. set_ink_tool(index: int) -> void: читать/подчеркнуть/обвести/стереть вместо удалённого OptionButton. Прежние сигналы выбора/закладки/позиции чтения/закрытия сохранены.

JournalPaperPages: bind, set_section, begin_edit, finish_edit(cancel=false) -> bool, request_page/can_request_page, note_rect. Двойной щелчок пишет/редактирует; Ctrl+Enter принимает, Esc отменяет текущую правку; drag перемещает заметку, Shift-drag создаёт стрелку (повтор той же пары убирает её), ПКМ меняет овал, Delete стирает выбранное. Пустая правка не удаляет запись. При слишком длинном тексте редактор остаётся открыт и блокирует перелистывание/закрытие без потери текста. Меню скрывает и блокирует страницу.

TextEdit с Caveat расположен прямо на бумаге; Main не перехватывает ввод J/T/B. Рецепты разбиваются BookPaginator по шрифту/области, оглавление рецептов/словаря по восемь заголовков, соседние записи доступны листанием. Словарные reading_offset/annotations привязаны к оригиналу и не сдвигаются от личного текста. UI держит записки в пределах листов по сторонам сгиба при resize.

Связи — гипотезы игрока, без автоматической проверки/влияния на диалоги. Свободное рисование/графическое досье/распознавание фактического напитка ещё не реализованы. История Ctrl+Z/Y относится к прежним пометкам слов и нативному активному редактору; undo завершённых личных блоков не добавлен.
